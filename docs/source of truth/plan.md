# План работы — кейс ekt.kz

Статус: **план, не отчёт о выполнении**. Ориентир — 5 часов хакатона. Требования: [PRD.md](PRD.md). Используем существующие FastAPI/Pydantic и Next.js/React; компоненты шаблона подключаем только по нуждам сценария.

1. **UC-01, первый сквозной результат.** Уточнить контракт каталога и настроить Basic Auth через локальные секреты. Проверить один известный и один неизвестный артикул. Соединить чат → API → реальное чтение каталога → ответ с проверяемыми фактами и проверкой результата.
2. **UC-02, консультация.** Добавить поиск аналогов по значимым характеристикам и остатку с объяснением выбора. Получить утверждённые условия покупки; проверить ответы об оплате, доставке и минимальной партии. При отсутствии источника честно обозначать ограничение.
3. **UC-03, безопасное действие.** Согласовать контракт корзины. Реализовать предложение с артикулом и количеством, отдельное согласие, повторную проверку остатка, изменение корзины и ссылку. Проверить отсутствие изменений до согласия, отмену и превышение остатка. Локальную корзину обозначать как демонстрационную.
4. **Остальные входы и сдача.** Поддержать фото и Excel/Word/PDF/JPEG в пределах разрешённой обработки данных, проверить мобильный экран. Провести сквозные прогоны UC-01…03, записать источник данных, результаты и ограничения, обновить README и отправить проверенную версию в репозиторий команды.

Если времени мало, сначала завершить UC-01 от ввода до результата, затем расширять эту цепочку. Недоступные API корзины, условия покупки или разрешения на обработку вложений фиксировать как внешние зависимости, не подменяя их выдуманными данными.
