# Use Cases — кейс ekt.kz

Источник обязательного поведения — [итоговое Word ТЗ HackAlem AI](<assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>); производные критерии — [PRD](PRD.md). **UC-01…05 строго соответствуют пяти пунктам раздела 7 ТЗ.** Первый сквозной приоритет — вопрос о товаре → факты каталога → видимый ответ. Остальные сценарии продолжают эту цепочку по потребности клиента.

## Ключевой путь из ТЗ

Частный покупатель или закупщик открывает чат на сайте → задаёт вопрос текстом либо прикладывает фото/Excel/Word/PDF/JPEG → получает сведения о товаре, аналогах или условиях → выбирает товар и количество → отдельно подтверждает → получает обновлённую корзину и прямую ссылку. Цель — быстрее принять решение о покупке и сократить типовые обращения к менеджерам.

## Обязательные сценарии

| UC / пункт раздела 7 | Вход | Наблюдаемый результат и критерий |
| --- | --- | --- |
| **UC-01 / 1** | Артикул/характеристики текстом или позиция из вложения | Существующий товар, верные наличие и технические характеристики; сертификат ссылкой/файлом, если есть в базе. Неизвестные сведения и ошибки источника обозначены. |
| **UC-02 / 2** | Запрос товара с нулевым остатком | Не менее одного существующего доступного аналога с кратким объяснением релевантности. Его свойства/остаток проверены. Отказ при недостатке данных не подменяет успешную приёмку контрольного случая. |
| **UC-03 / 3** | Вопрос об оплате, доставке и минимальной партии | Содержательный ответ по всем темам на основании источника. Отсутствие общего правила и неоднозначности явно обозначены, условия не выдуманы. |
| **UC-04 / 4** | Выбранные позиции/количества и затем отдельное «да, добавь» | До согласия корзина прежняя; после него изменена только корзина текущего пользователя, количество не превышает остаток. Отмена, двусмысленный ответ и устаревшее предложение не разрешают изменение. |
| **UC-05 / 5** | Успешный UC-04 | Прямая ссылка открывает актуальную корзину с подтверждённым составом/количеством. |

Фото и документы из раздела 5 — варианты входа в эти же UC, а не отдельные Must have. Сам файл не является согласием. Ограничения раздела 9: не изменять корзину/заказ без явного согласия; не выдумывать цену/наличие; не запрашивать и не хранить платёжные данные; учитывать приватность, защиту действий, объяснимость и desktop/mobile.

## Как выполнить сценарии в текущем приложении

Готовые пошаговые прогоны, сообщения и входные документы находятся в [out/README.md](../../out/README.md), [out/use-cases.md](../../out/use-cases.md) и [out/expected-results.md](../../out/expected-results.md). Они конкретизируют применение требований к прототипу и не заменяют Word ТЗ.

**Уточнение заказчика от 23.09.2026:** корзину организовать на нашей стороне с будущим переключением на ekt.kz. Поэтому текущие UC-04/05 проверяют серверную корзину приложения. В коде есть `CartAdapter`; фактическая интеграция корзины/оформления магазина — следующий этап. Автономная корзина вкладки в режиме снимка остаётся отдельно обозначенной демонстрацией.

Уже выполненные прогоны и текущие ограничения записаны в [ROADMAP](../../ROADMAP.md) и [CHANGELOG](../../CHANGELOG.md). Живой путь UC-01…05 проверен на desktop/mobile; сертификат с настоящей ссылкой в контрольных карточках пока не найден, старый DOC отдельно не проверен. Цена/остаток всегда проверяются при новом обращении: записанное наблюдение не является гарантией текущих значений.

Поддержка казахского языка, сопутствующие товары, история авторизованного клиента и передача менеджеру остаются опциональными по разделу 8 ТЗ; обязательные сценарии ими не расширяются.
