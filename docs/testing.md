# Проверка сценариев HackAlem

Проверки связаны с пятью Must have [Word ТЗ](<source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>). Выполняйте нужный уровень после изменения; синтетические фикстуры и живые интеграции имеют разные результаты проверки.

## Офлайн, без ключей и внешних запросов

```bash
make check
make test
make test-ui
make build-frontend
```

- `backend/tests/test_landing.py`: предоставленные JSON соответствуют контракту; количество, отдельное согласие, повтор, отмена, срок предложения, смена цены/остатка, атомарность набора, удаление и изоляция сессий. Проверяются расширенный поиск аналогов, исключение аксессуаров/другого тока, нулевой остаток в нескольких результатах и запросе добавления, структура условий покупки. Дополнительно проверяются статусы каждой распознанной строки, неоднозначный единственный результат, отсутствие количества, повторы вместе с текущей корзиной, кратность и отказ каталога без потери строки. Детальные карточки здесь подменены управляемыми фикстурами; OpenAI и ekt.kz не вызываются.
- Те же тесты проверяют восемь существующих входов из `out/manifest.json`, контрольные суммы и сохранение кодов офисных файлов. Они используют те же закупочные документы.
- `frontend/e2e/landing.spec.ts`: 22 проверки на desktop/mobile: 14 автономного HTML и 8 с управляемыми API-ответами. Проверка спецификации охватывает видимость исключений, отсутствие подстановки количества, выбор/снятие строк, объединение повторов, отмену устаревшего предложения и отдельное согласие. Проверяется новый вход с лендинга через выбор файла: один чат, сохранение черновика, отсутствие отправки/добавления без действия пользователя. Управляемые ответы проверяют видимость позиций при повторном открытии корзины, фокус без вызова клавиатуры, открытие во время другого запроса, `/cart` после обновления и безопасную разметку условий оплаты/доставки. Запускается временный статический сервер; внешние API подменены явно.
- Дополнительно: полезные подсказки с сохранением отдельного согласия, отсутствие скрытого предложения после сбоя модели, черновик менеджера без истории/вложений; браузер проверяет редактирование, копирование, безопасный вывод и контакты при отключённом backend. Копирование не выполняет отправку.
- Генераторы `backend/generate_*_openapi.py --check`: соответствие JSON-контрактов моделям Pydantic. Это не доказательство поведения.
- ESLint/TypeScript и `next build --webpack`: рабочий React-лендинг Next.js 16 и общий DOM/JS чат, извлечённый из `index.html`. Генерация выполняется автоматически перед сборкой/запуском.

Для браузерных проверок установите Chromium и системные библиотеки: из `frontend/` выполните `npx playwright install --with-deps chromium`. `make install` использует `backend/uv.lock` и `frontend/package-lock.json`.

## Живой прогон

```bash
make test-live
```

В локальном `backend/.env` должны быть ключ OpenAI и доступ к ekt.kz. Живой Playwright открывает настоящий `app.landing` на порту 8766, сверяет карточку с API, проверяет минимум один аналог для `ярп4520` и `310100080_`, условия покупки, явное согласие, повторное открытие `/cart` и удаление. Дополнительные сценарии: XLSX с двумя листами → четыре строки с повтором → три позиции/6 единиц после согласия; JPEG накладной → две исходные позиции; вопросы о заказе с опечатками и связь с менеджером. Каждый проходит на desktop/mobile.

`make test-files-live` отдельно загружает все восемь файлов через ASGI-приложение с настоящими OpenAI и HTTP API ekt.kz. Сравнивает исходные ID/количества, повторы, неизвестное количество, свойства/цены/склады, аналоги и корзину. Для мелкой неоднозначной маркировки фото критерий — честный запрос уточнения, отсутствие точного выбора и правильный товар после кода от покупателя; `direct_match=false` сохраняется. Четыре разговорные реплики проверяются отдельно. Отчёт хранит предыдущие неудачные попытки и хеши проверенной реализации.

Вызовы модели расходуют API-бюджет. Остатки меняются: при изменении контрольной позиции сначала проверьте источник, не подгоняйте ожидания под ошибку.

CI выполняет только проверки без внешних секретов и сборку контейнера. Живые прогоны запускаются явно. Общий статус — [ROADMAP](../ROADMAP.md); [out/verification.json](../out/verification.json) — датированная проверка файлов, а не автоматически обновляемый отчёт CI.

В живом наборе вход по артикулу и выбор XLSX начинаются с новых кнопок лендинга. До отправки выбранный файл не вызывает сообщение модели и не изменяет корзину. Это проверка пользовательского входа. Пользу для закупщика и сравнение способов работы измеряют отдельно по [протоколу](product-value.md#как-проверить-пользу).

Для ручного показа: [out/use-cases.md](../out/use-cases.md). Положительный живой пример сертификата и старый DOC пока не подтверждены. Нельзя объявлять их проверенными только по успешному HTTP-коду или наличию ссылки в шаблоне ответа.


## Проверка переноса в Next.js

`make test-next-ui` собирает production frontend, затем повторяет существующие браузерные сценарии через Next.js на порту 3080. API здесь подменяются фикстурами либо недоступны для проверки деморежима. Дополнительно проверяются отсутствие iframe, JavaScript-ошибок и горизонтального переполнения, открытие того же чата с нового лендинга, менеджер и `prefers-reduced-motion`.

`make test-next-live` запускает Next.js на 3081 и FastAPI на 18766: реальные каталог/OpenAI, все пять UC, закупочный Excel, JPEG, подсказки и менеджер. Отдельно проверяются Origin, cookie HttpOnly/SameSite, CSRF и изоляция сессий через новый прокси. Прямой `/cart` и перезагрузка должны сохранить состав. Playwright использует `playwright.next.config.ts`; внешние вызовы требуют `.env` и расходуют API-бюджет.

Старые HTML-наборы сохранены. Backend, контракты и бизнес-логика этого переноса не изменялись; повторный файловый live-прогон всех форматов не заменяет браузерную проверку нового origin.
