# Архитектура ассистента HackAlem

Источник поведения — [Word ТЗ](<source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>). Все пять обязательных сценариев работают через одну цепочку:

```text
Next.js React-лендинг + общий DOM/JS чат из index.html
  → Next.js /api (проверка Origin, cookie/CSRF)
  → FastAPI app.landing /api/chat
      → OpenAI: намерение, позиции, количества, чтение фото/PDF
      → ekt.kz: поиск, детальная карточка, остатки, документы, условия
  → предложение /api/cart/prepare
  → отдельное явное согласие /api/cart/confirm
      → повторная проверка → CartAdapter → ServerCart
  → /cart → та же Next.js страница и корзина текущей сессии
```

## Состав репозитория

| Часть | Назначение по ТЗ |
| --- | --- |
| `index.html` | Исходник общего чата (ввод, карточки, вложения, согласие, корзина) и самостоятельный HTML-лендинг; desktop/mobile. |
| `backend/app/landing.py` | UC-01…05, Pydantic входы/выходы, OpenAI, интеграция каталога, файлы и сессии. |
| `backend/app/schemas/ekt_catalog.py` | Наблюдаемая схема API партнёра; общая для шлюза и генератора OpenAPI. |
| `contracts/` | Генерируемые контракты каталога и нашего API, описание границ интеграции. |
| `frontend/src/` | React-лендинг Next.js 16 / Tailwind / shadcn, изолированный общий чат, маршруты `/cart` и `/api`. |
| `frontend/e2e/` | Проверки рабочего лендинга и пяти UC на двух размерах экрана. |
| `backend/tests/` | Проверки количества, согласия, изоляции, атомарности, контрактов и существующих файлов `out/`. |
| `out/` | Закупочные документы и результаты живых проверок; приложение не использует их как готовые ответы. |

## Модель и факты

OpenAI возвращает структурированное намерение. Сервер определяет товар по коду/артикулу и запрашивает API с Basic Auth. Модель не задаёт цену/остаток и не вызывает изменение корзины напрямую. Начальная выборка служит индексом кодов; подробные данные серверного режима читаются у партнёра. При отсутствии сведений выдаётся уточнение/ограничение.

Word/Excel/TXT/CSV читаются на сервере; PDF и изображения передаются модели после проверки. Байты документов не записываются на диск. Подробности — [file-processing.md](file-processing.md).

## Связь с менеджером

`GET /api/manager` не требует OpenAI: читает опубликованные каналы `ekt.kz/about/contacts/` (кеш 15 минут) и возвращает `ManagerHelp`. Черновик содержит проверенный текущий товар и состав корзины, без истории или вложений. UI экранирует текст, разрешает его редактирование/копирование и открывает контакты только по действию пользователя. `sent=false`: запрос в CRM или сообщение оператору не создаётся. Недоступный источник оставляет ссылку на сайт, без выдуманного телефона.

## Корзина и приватность

Сессия использует HttpOnly/SameSite cookie, CSRF и проверку Origin. Одноразовое предложение действует 3 минуты и связано с версией корзины. Цена, кратность и остатки повторно проверяются для всего набора до изменения. Файл или «ок» не дают разрешения. Удаление тоже подтверждается.

`ServerCart` хранит состояние в памяти одного процесса: обновление страницы его сохраняет, перезапуск/час бездействия очищает. `CartAdapter` — точка будущего подключения корзины ekt.kz после получения контракта и правил идентификации клиента. БД добавляется, когда реализуется постоянная корзина/история с подтверждёнными требованиями.

## Next.js и общий чат

`sync-assistant.mjs` извлекает разметку, стили, начальную выборку и рабочий JS из `index.html` перед dev/build. Стили ограничены `.assistant-widget`, тема задаётся `widget-theme.css`. Генерируемые JSON/CSS/JS не редактируются и не коммитятся. `AssistantWidget` в root layout владеет стабильным контейнером; React не пересоздаёт содержимое чата. Скрипт запускается один раз после гидратации, кнопки лендинга — после готовности. iframe отсутствует.

`ASSISTANT_API_URL` — только серверная настройка Next.js. Прокси проверяет Origin перед его преобразованием для FastAPI, передаёт CSRF/cookie и возвращает Set-Cookie без кеширования. Проверки подтверждения/остатка/изолированной сессии остаются на backend. `/cart` и обновление страницы используют тот же origin. Пользовательские файлы не попадают в React server state или в сборочные артефакты.

Лендинг перенесён в React; полный перенос рендера сообщений не выполнен по выбранному простому пути миграции. API-контракт не изменён. Исходный HTML остаётся отдельным рабочим режимом на FastAPI.

## Зависимости и развёртывание

Backend содержит только FastAPI/Uvicorn, Pydantic, HTTPX, OpenAI SDK, dotenv, BeautifulSoup и обработчики заявленных форматов. Docker Compose запускает один контейнер, один worker и получает секреты из `backend/.env`. Образ собирается из корня, включает HTML и два файла каталога; `.env`, документы с доступом и `out/` в образ не копируются.

Контейнер сейчас предназначен для локального прототипа. Постоянное хранилище, HTTPS/маршрутизация действующего домена и ограничение нагрузки остаются стадией размещения из [ROADMAP](../ROADMAP.md).
