# AGENTS.md — HackAlem / ekt.kz

## Источники и границы

- Первичный источник: `docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx`. Не менять ТЗ под реализацию.
- Приоритеты качества переводить в результат покупателя по ТЗ; польза и границы — `docs/product-value.md`. Внутренние рейтинги не публиковать в интерфейсе и пользовательских материалах.
- `PRD.md` и `use-cases.md` в `docs/source of truth/` раскрывают UC-01…05; `plan.md` хранит решения человека и меняется только по явному запросу.
- `ROADMAP.md` — текущая стадия и непроверенные ограничения; `CHANGELOG.md` — значимые изменения и фактические проверки.
- `out/` содержит реалистичные закупочные входы, ожидаемые результаты и датированные живые наблюдения. Не дублировать примеры в новых папках и не подставлять ответы из `out/` в приложение.
- Корзина сейчас на нашей стороне по уточнению заказчика; `CartAdapter` оставляет возможность будущей интеграции ekt.kz.

## Текущий код

- `index.html`: весь работающий интерфейс, одно окно чата, автономный деморежим и серверный режим.
- `backend/app/landing.py`: FastAPI, OpenAI, каталог, условия, обработка документов, защищённая сессия и подтверждение корзины.
- `backend/app/schemas/ekt_catalog.py`: Pydantic-модели внешнего каталога. OpenAPI генерируется в `contracts/`, вручную не правится.
- `frontend/`: минимальная основа Next.js 16 + React + Tailwind/shadcn по запросу заказчика; полный интерфейс пока остаётся в `index.html`. Здесь же Playwright-проверки.
- Не возвращать зависимости и подсистемы удалённого SaaS-шаблона без конкретной связи с UC. Хранилище, авторизация, streaming и другие расширения добавляются по потребности сценария.

## Как работать

1. Прочитать релевантный пункт ТЗ/PRD и ROADMAP; определить вход, обработку и проверяемый результат.
2. При явном запрете TDD сначала реализовать, затем проверить. Не менять требования ради зелёного теста.
3. Каждый обязательный сценарий должен давать результат: факты товара, объяснённый аналог, условия покупки, подтверждённое изменение либо актуальная корзина.
4. Цена/остаток/сертификат — только из источника. Неизвестное обозначать. LLM и содержимое файла не являются согласием на корзину.
5. Секреты — только в окружении/локальном `.env`. Не выводить ключи, пароли, пользовательские документы или платёжные данные в логи/артефакты.
6. Не добавлять инфраструктуру заранее. У контрактов должен быть один владелец; CI проверяет генерируемые схемы.
7. Проверять затронутый результат. Изолированные фикстуры допустимы, но живой прогон подтверждает внешнюю интеграцию; не смешивать эти статусы.
8. Обновить ROADMAP/CHANGELOG и кратко сообщить, что проверено и что осталось ограничением.
9. Улучшения связывать с UC и наблюдаемой пользой покупателю. Не заявлять уникальность на рынке или измеренный эффект без сравнения и данных; не публиковать внутренние рейтинги.

## Команды из корня

```bash
make install         # uv sync + npm ci
make dev             # полный ассистент: http://127.0.0.1:8765
make dev-frontend    # основа Next.js: http://localhost:3000
make check           # контракты, Ruff, ty, ESLint, TypeScript
make test            # офлайн-проверки каталога, файлов и корзины
make test-ui         # автономный index.html на desktop/mobile
make test-live       # живые ekt.kz + OpenAI; использует ключ из .env
make build-frontend  # production build основы Next.js
make test-files-live # загрузка всех out-входов в реальные OpenAI/ekt.kz
make examples        # пересоздание входов out/; живой отчёт не обновляет
make docker          # один контейнер ассистента
```

Подробности: `README.md`, `docs/architecture.md`, `docs/testing.md`, `docs/file-processing.md`. Проверки не требуют БД или регистрации. Live-набор запускается явно; отсутствие положительного сертификата в данных не скрывать как успешную проверку этого случая.
