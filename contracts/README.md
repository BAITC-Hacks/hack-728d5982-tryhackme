# Контракты интеграций

Эта папка показывает, какие данные проходят между клиентом, нашим API, хранилищем и внешними сервисами. Для каждого подтверждённого интерфейса здесь фиксируются метод и путь, параметры запроса, заголовки и авторизация, схема ответа, ошибки, источник типов и способ проверки. Требования к поведению остаются в [PRD](../docs/source%20of%20truth/PRD.md).

| Граница | Источник схемы | Что есть сейчас |
| --- | --- | --- |
| **Backend ↔ каталог ekt.kz**, UC-01 (далее UC-02/04) | [Pydantic-модели](../backend/app/schemas/ekt_catalog.py) → [OpenAPI 3.1](ekt-catalog.openapi.json) | [Наблюдаемый контракт](ekt-catalog-api.md): `GET /api/products`, `GET /api/products/detail?id=…`, Basic Auth по HTTPS, параметры, поля `200` и ошибки `400`/`401`/`404`. Это API партнёра; наши маршруты его пока не реализуют. |
| **Frontend ↔ наш FastAPI**, первым будет UC-01 | Pydantic-схемы и маршруты в `backend/app/` → OpenAPI FastAPI → генерируемые типы frontend | Продуктовый запрос о товаре и его ответ ещё не реализованы. Существующие маршруты шаблона не считаются контрактом UC-01. После реализации здесь нужна ссылка на конкретный маршрут, заголовки/сессию, запрос, ответ и ошибки. |
| **Backend ↔ БД** | Модели `backend/app/db/models/` и миграции `backend/alembic/versions/` | В репозитории есть схема БД шаблона. Отдельная продуктовая схема для каталога или корзины не утверждена; хранение добавляется только при необходимости UC и сопровождается миграцией. |

**Поток UC-01:** браузер → frontend → наш backend → каталог ekt.kz → проверка Pydantic → ответ клиенту. Basic Auth партнёра используется только backend и не попадает в браузер или OpenAPI-файл. Для внешнего запроса подтверждены `Authorization: Basic …` и JSON-ответ; формат запроса frontend ↔ backend пока не определён. `CatalogProductFacts` в OpenAPI — целевой внутренний набор фактов, а не ответ API партнёра.

Из `backend/` проверить, что OpenAPI-файл соответствует Pydantic-моделям:

```bash
uv run python generate_ekt_catalog_openapi.py --check
```

Эта же проверка запускается в CI. Схема подтверждает форму данных, а пользовательский результат UC-01 требует отдельного сквозного прогона. Секреты, реальные клиентские данные и неподтверждённые контракты здесь не сохраняются.
