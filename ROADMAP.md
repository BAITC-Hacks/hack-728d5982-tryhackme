# ROADMAP — ИИ-ассистент для ekt.kz

Статус на 23.09.2026: план; выполнение этапов не подтверждено сквозными прогонами. [PRD](docs/source%20of%20truth/PRD.md) задаёт поведение и приёмку UC-01…03; [plan.md](docs/source%20of%20truth/plan.md) задаёт краткую последовательность работы в рамках хакатона. Здесь перечислены функции и измеримые результаты этапов. Приоритет — сначала один работающий путь UC-01, затем расширение той же цепочки для UC-02 и UC-03.

## Фаза 1 — MVP хакатона

### M0. Минимальная основа и проверка доступов — UC-01, подготовка UC-02/03

- [ ] **Есть в репозитории:** учесть возможности шаблона — Next.js чат, FastAPI, Pydantic, WebSocket агент, JWT авторизацию и хранение диалогов, загрузку файлов, PostgreSQL; продуктовый сценарий ими пока не подтверждён.
- [ ] **Нет для кейса:** определить подключение каталога ekt.kz, схему товаров и остатков, утверждённые условия покупки, контракт корзины, ориентированный на покупателя чат и сценарные проверки. Связь авторизации шаблона с покупателем и корзиной ekt.kz пока не установлена.
- [ ] **Сделать:** проверить доступные endpoints каталога и правила использования данных.
- [ ] Выбрать один контрольный артикул, отсутствующий артикул и позицию с нулевым остатком.
- [ ] Безопасно хранить Basic Auth вне кода и документации.
- [ ] Зафиксировать нормализованную модель товара (артикул, характеристики, сертификат, цена, остаток, источник и время получения) как общий контракт UC-01/02/03.
- [ ] Вопросы о корзине, условиях и встраивании отправить партнёру параллельно, без блокировки первого текстового прогона.
- [ ] **Выход:** получить воспроизводимый запрос к каталогу или явно помеченной демонстрационной выборке и перечень подтверждённых полей. Ни один ответ ассистента ещё не считается проверенным.

### M1. Первый сквозной сценарий товара — UC-01

- [ ] **Функции:** провести запрос через минимальный покупательский чат → API → поиск по артикулу → реальное получение деталей и остатка → текстовый ответ с характеристиками, статусом наличия и сертификатом, если он есть.
- [ ] При неизвестном артикуле или сбое источника сообщать об этом без вымышленных данных.
- [ ] Начать с текстового ввода и одного товара; использовать модель M0 для ответа, чтобы затем добавить аналоги и корзину без второго независимого каталога.
- [ ] **Выход:** контрольный запрос в браузере возвращает те же характеристики и остаток, что источник; отсутствие товара и сертификата отражено корректно.
- [ ] API-тест проверяет значения и ошибку источника, браузерный тест — доступность результата пользователю.
- [ ] Зафиксировать, был ли прогон живым или на демонстрационных данных.

### M2. Сессия покупателя и граница действий — UC-01, подготовка UC-03

- [ ] **Функции:** связать контекст диалога с конкретным покупателем или защищённой гостевой сессией.
- [ ] Решить способ авторизации для будущей корзины с учётом платформы ekt.kz; исключить доступ к чужой сессии.
- [ ] Задать состояния выбора: найденный товар → предложенное количество → ожидание подтверждения → подтверждено/отменено.
- [ ] Сделать изменение корзины технически недоступным до подтверждения.
- [ ] **Выход:** повторное сообщение в той же сессии относится к выбранному товару; другая сессия его не видит.
- [ ] Использовать JWT шаблона только после проверки пригодности для покупательского сценария; интеграция с аккаунтом ekt.kz остаётся отдельной зависимостью.

### M3. Консультация по аналогам и покупке — UC-02

- [ ] **Функции:** при нулевом остатке искать доступный аналог по значимым характеристикам из той же модели каталога, кратко объяснять совпадения и отличия.
- [ ] Отвечать об оплате, доставке и минимальной партии только из утверждённого источника.
- [ ] При отсутствии аналога или источника условий сообщать ограничение.
- [ ] **Выход:** запрос отсутствующей позиции возвращает существующий релевантный аналог с обоснованием; вопросы по трём условиям имеют подтверждённые ответы.
- [ ] Проверка сопоставляет артикул, остаток и ключевые характеристики аналога с каталогом.

### M4. Подтверждаемое добавление в корзину — UC-03

- [ ] **Функции:** получить контракт корзины ekt.kz.
- [ ] Показать артикул и количество перед действием; принять отдельное явное согласие.
- [ ] Повторно проверить остаток; изменить только корзину текущего покупателя; вернуть ссылку на её актуальное состояние.
- [ ] Отмена, двусмысленный ответ, изменение позиции/количества и превышение остатка не выполняют действие.
- [ ] **Выход:** сравнение корзины до предложения, до согласия и после него подтверждает единственное ожидаемое изменение; ссылка открывает обновлённую корзину.
- [ ] Если контракт партнёра не предоставлен, локальная корзина помечена как демонстрационная, а UC-03 с ekt.kz остаётся невыполненным.

### M5. Остальные обязательные входы и приёмка MVP — UC-01…03

- [ ] **Функции:** извлекать артикулы/свойства из разрешённых фото и Excel, Word, PDF, JPEG; передавать найденные позиции в ту же цепочку UC-01…03.
- [ ] Проверить интерфейс на мобильном экране, защиту данных вложений, отсутствие платёжных данных в обработке и задержку ответа в пределах единиц секунд при доступном источнике.
- [ ] **Выход:** провести живые пользовательские прогоны всех трёх UC с фиксацией входа, источника, результата и проверки критериев PRD.
- [ ] Обновлённые README и журнал значимых изменений отражают только доказанную готовность.
- [ ] Считать MVP завершённым лишь при работе с фактическими данными и корзиной партнёра; прогон с синтетическим каталогом или локальной корзиной остаётся демонстрацией прототипа.

## Фаза 2 — после MVP

После подтверждения UC-01…03 можно добавить опциональные функции из PRD: казахский язык, сопутствующие товары, историю диалогов для авторизованных покупателей и передачу сложных вопросов менеджеру. Каждая из них требует отдельного пользовательского результата и проверки; до этого они не задерживают основной путь.

## Внешние зависимости и порядок решений

| Зависимость | Что блокирует | Временный путь без ложной готовности |
| --- | --- | --- |
| Схема, доступ и разрешённое использование API каталога | Живую проверку UC-01/02 и остатка для UC-03 | Репрезентативная выборка, явно помеченная как демонстрационная |
| Утверждённые условия оплаты, доставки, партии | Полную приёмку UC-02 | Сообщение, что условия не подтверждены |
| Контракт и доступ к корзине ekt.kz, привязка покупателя | Живую приёмку UC-03 | Локальная корзина только для демонстрации логики согласия |
| Правила встраивания и обработки вложений | Работа на сайте и часть входов UC-01…03 | Локальный чат; не передавать клиентские файлы сторонним сервисам без разрешения |

При дефиците времени следующий шаг всегда определяется ближайшим непроверенным результатом UC-01. Наличие готового слоя шаблона или зелёного теста на моках само по себе не закрывает milestone.
