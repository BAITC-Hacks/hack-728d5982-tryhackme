# ИИ-ассистент для покупателей ekt.kz

Прототип для кейса HackAlem AI от ТОО «Электрокомплект». Покупатель должен получать в чате сведения о товаре, наличии, сертификатах, аналогах и условиях покупки, а после явного согласия — добавлять выбранный товар в корзину. Первичный источник требований — [итоговое Word ТЗ HackAlem AI](<docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>); критерии приёмки раскрыты в [PRD](docs/source%20of%20truth/PRD.md), ближайшие шаги — в [плане](docs/source%20of%20truth/plan.md).

## Текущий статус

Репозиторий пока содержит **Full-Stack AI Agent Template**, а не завершённый ассистент для ekt.kz. В шаблоне есть общий интерфейс чата и FastAPI backend. В коде пока нет подключения к каталогу ekt.kz, поиска товарных аналогов, подтверждаемого добавления в корзину и проверок сценариев кейса. Общий чат не подтверждает выполнение PRD. Инструкция и возможности исходного шаблона сохранены в [README.template.md](README.template.md).

## Требуемый сценарий

Покупатель задаёт вопрос или прикладывает спецификацию → ассистент получает факты из каталога и отвечает с учётом наличия → при отсутствии позиции предлагает обоснованный аналог → отвечает об условиях покупки → показывает товар и количество для подтверждения → только после явного согласия обновляет корзину → даёт ссылку на неё. Первый приоритет — сквозной UC-01 (вопрос о товаре → факты каталога → ответ). Остальные пункты Must have из Word ТЗ — UC-02 (аналоги), UC-03 (условия), UC-04 (добавление после согласия), UC-05 (ссылка); критерии находятся в [PRD](docs/source%20of%20truth/PRD.md).

## Технологии и архитектура текущего репозитория

| Компонент | Что есть в коде | Роль в кейсе |
| --- | --- | --- |
| `frontend/` | Next.js 15, React 19, Tailwind, интерфейс общего чата | Будущий покупательский чат |
| `backend/` | FastAPI, Pydantic, общие chat API и AI-агент | Будущие запросы к каталогу и правила подтверждения |
| Хранение | PostgreSQL, Redis, RAG-компоненты шаблона | Использовать только по необходимости сценария |
| Каталог ekt.kz | В материалах есть API чтения товаров | Интеграция ещё не реализована и не проверена |
| Корзина ekt.kz | Контракт в материалах отсутствует | Требуется согласовать с партнёром |

Целевой путь данных для UC-01: браузер → frontend → backend → источник каталога → ответ; для UC-04 backend меняет корзину только после подтверждения и повторной проверки остатка, а UC-05 возвращает ссылку. Это план, а не описание работающей интеграции.

## Локальный запуск имеющегося шаблона

Нужны Docker с Compose и Make. Frontend можно запустить в Docker; для локального режима нужен Bun. Команды из корня репозитория:

```bash
make dev            # backend, БД, миграции; API на http://localhost:8000
make dev-frontend   # frontend на http://localhost:3000
```

Для входа в существующий чат шаблона может понадобиться тестовый пользователь. В локальной среде его создаёт `make seed`; демонстрационные учётные данные указаны в [README.template.md](README.template.md) и не предназначены для публичного развёртывания. Документация API: <http://localhost:8000/docs>. Для остановки backend: `make dev-down`; frontend управляется отдельным `docker-compose.frontend.yml`.

Перед использованием AI-функций шаблона настройте `backend/.env` по `backend/.env.example`, включая свой `OPENAI_API_KEY`. Учётные данные API ekt.kz есть только в предоставленном партнёром документе `docs/source of truth/assets/ИИ-ассистент для чата на сайте ekt.kz ДАННЫЕ.docx`; их следует держать в локальной конфигурации/секретах и не публиковать. Пока интеграции нет, добавление этих данных в `.env` само по себе не подключит каталог.

## Как проверить сейчас

После запуска откройте frontend и `/docs`, проверьте доступность общего чата и API. Тесты шаблона запускаются `make test` для backend и `cd frontend && bun run test:e2e` для браузера. Они **не проверяют** товарные данные, аналоги или корзину ekt.kz. Ближайшая воспроизводимая проверка из [плана](docs/source%20of%20truth/plan.md) — UC-01: запрос артикула в чате, фактическое чтение каталога и видимый ответ с совпадающими характеристиками и остатком. После неё проверяются UC-02…05.

## Данные, внешние сервисы и ограничения

Материалы партнёра указывают `GET https://ekt.kz/api/products` (страницы через `?page=…`) и `GET https://ekt.kz/api/products/detail?id=…` с Basic Auth. Доступ и наблюдаемая схема ответов проверены 23.09.2026; подробности — в [контракте каталога](contracts/ekt-catalog-api.md) и [карте контрактов](contracts/README.md). Это ещё не проверка интеграции с чатом. Разрешённая заданием анонимизированная или синтетическая выборка подходит для демонстрации поведения, но не подтверждает актуальность остатков ekt.kz. Источник условий покупки, доступ к корзине и способ встраивания на сайт предстоит уточнить. Развёрнутой версии кейса пока нет.

Документы хакатона находятся в `docs/source of truth/assets/`; перед публикацией проекта нужно проверить репозиторий на секреты и соблюдать правила организаторов по работе с данными.
