# ИИ-ассистент для покупателей ekt.kz

Прототип для кейса HackAlem AI от ТОО «Электрокомплект». Покупатель должен получать в чате сведения о товаре, наличии, сертификатах, аналогах и условиях покупки, а после явного согласия — добавлять выбранный товар в корзину. Первичный источник требований — [итоговое Word ТЗ HackAlem AI](<docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>); критерии приёмки раскрыты в [PRD](docs/source%20of%20truth/PRD.md), ближайшие шаги — в [плане](docs/source%20of%20truth/plan.md).

## Текущий статус

В [index.html](index.html) реализован адаптивный лендинг с одним раскрывающимся окном чата. В нём доступны поиск по примерам каталога, карточки со свойствами и складами, сравнение похожих позиций, выбор количества, явное подтверждение и ссылка на локальную корзину. Серверный шлюз [backend/app/landing.py](backend/app/landing.py) читает живой каталог с Basic Auth, не передавая пароль браузеру. Это прототип интерфейса и поиска по данным: языковая модель, подтверждённые условия покупки и корзина ekt.kz ещё не подключены. Полное выполнение ТЗ пока не подтверждено.

### Запуск лендинга

Откройте `index.html` в браузере: встроены 40 позиций из предоставленных `products.json` и `products _page_2.json`, одна детальная карточка из `detail.json`. Снимок явно обозначен; остатки других позиций не придуманы. `index(1).html` оставлен без изменений.

Для живых карточек запустите из `backend/`:

```bash
# EKT_API_USER и EKT_API_PASSWORD задайте в окружении сервера.
# Если секреты лежат в локальном .env, добавьте к команде --env-file .env.
uv run uvicorn app.landing:app --host 127.0.0.1 --port 8765
```

Откройте <http://127.0.0.1:8765/>. Без этих переменных лендинг использует снимок; с ними `/api/catalog/detail?id=…` и `/api/catalog?page=…` получают данные ekt.kz, проверяя существующими Pydantic-моделями. Поиск выполняется по загруженной части каталога, страницы можно догружать в чате. Для этого отдельного запуска не нужны БД, Redis или вход в шаблон. Это локальный стенд; ограничения публичного шлюза и встраивание в действующий магазин ещё предстоит согласовать.

Проверка интерфейса: `cd frontend && npm run test:landing`. Она запускает отдельный статический сервер и Chromium, проверяет десктоп и мобильный экран без авторизации шаблона. В среде должны быть установлены браузер и системные зависимости Playwright.

**Границы демонстрации:** корзина сохраняется в `sessionStorage` текущей вкладки, ссылка `#cart` открывает её актуальное состояние внутри того же чата; заказ не создаётся. «Ок» не считается подтверждением, количество проверяется относительно остатка и кратности; перед добавлением живые данные запрашиваются повторно. Валюта не приписывается цене, поскольку в API она отсутствует. Расхождение 160 А в названии и 250 А в свойствах контрольного товара показывается явно. Похожие названия не выдаются за подтверждённую взаимозаменяемость. Условия оплаты и доставки требуют источника партнёра.

Вложения читаются в браузере: TXT/CSV, XLS/XLSX, DOCX, PDF с текстовым слоем; JPEG/PNG — распознавание надписей через OCR, а не распознавание модели товара по внешнему виду. Библиотеки загружаются с jsDelivr при первом использовании. Лимиты: 5 файлов по 8 МБ, PDF до 10 страниц, Excel до 5 листов и 300 строк на лист; извлечённый текст до 24 000 символов. Старый Word `.doc` требует пересохранения в `.docx`, скан PDF — отдельного JPEG. Файлы не отправляются AI-сервисам. Их содержимое не считается согласием на изменение корзины.

Инструкция исходного шаблона сохранена в [README.template.md](README.template.md).

## Требуемый сценарий

Покупатель задаёт вопрос или прикладывает спецификацию → ассистент получает факты из каталога и отвечает с учётом наличия → при отсутствии позиции предлагает обоснованный аналог → отвечает об условиях покупки → показывает товар и количество для подтверждения → только после явного согласия обновляет корзину → даёт ссылку на неё. Первый приоритет — сквозной UC-01 (вопрос о товаре → факты каталога → ответ). Остальные пункты Must have из Word ТЗ — UC-02 (аналоги), UC-03 (условия), UC-04 (добавление после согласия), UC-05 (ссылка); критерии находятся в [PRD](docs/source%20of%20truth/PRD.md).

## Технологии и архитектура текущего репозитория

| Компонент | Что есть в коде | Роль в кейсе |
| --- | --- | --- |
| `index.html` | Самостоятельный лендинг и единое окно покупательского чата | Проверяемый интерфейс кейса; локальная корзина |
| `frontend/` | Next.js 15, React 19, Tailwind, интерфейс общего чата; Playwright-проверки лендинга | Шаблон и инструменты проверки |
| `backend/` | FastAPI, Pydantic, отдельный `app.landing` и общие API шаблона | Чтение каталога через сервер; существующие AI-компоненты шаблона |
| Хранение | PostgreSQL, Redis, RAG-компоненты шаблона | Использовать только по необходимости сценария |
| Каталог ekt.kz | API чтения через шлюз, Basic Auth только на сервере | Живые карточка и пагинация проверены; полный поиск и сертификаты требуют уточнения |
| Корзина ekt.kz | Контракт в материалах отсутствует | Требуется согласовать с партнёром |

Путь лендинга для UC-01: запрос → поиск артикула в загруженных позициях → серверный шлюз → карточка ekt.kz → ответ в чате. В режиме снимка источником служат встроенные примеры JSON. UC-04/05 демонстрируются локально в браузере; изменение настоящей корзины на сервере магазина остаётся отдельной задачей.

## Локальный запуск имеющегося шаблона

Нужны Docker с Compose и Make. Frontend можно запустить в Docker; для локального режима нужен Bun. Команды из корня репозитория:

```bash
make dev            # backend, БД, миграции; API на http://localhost:8000
make dev-frontend   # frontend на http://localhost:3000
```

Для входа в существующий чат шаблона может понадобиться тестовый пользователь. В локальной среде его создаёт `make seed`; демонстрационные учётные данные указаны в [README.template.md](README.template.md) и не предназначены для публичного развёртывания. Документация API: <http://localhost:8000/docs>. Для остановки backend: `make dev-down`; frontend управляется отдельным `docker-compose.frontend.yml`.

Перед использованием AI-функций шаблона настройте `backend/.env` по `backend/.env.example`, включая свой `OPENAI_API_KEY`. Учётные данные API ekt.kz из предоставленного партнёром документа следует держать в локальной конфигурации/секретах и не публиковать. Отдельный сервер лендинга использует `EKT_API_USER` и `EKT_API_PASSWORD`; он не зависит от ключа языковой модели.

## Как проверить сейчас

Проверки лендинга запускаются `cd frontend && npm run test:landing`: 10 сценариев на двух размерах экрана, без моков ответов (используется явно помеченная встроенная выборка). Живой ручной прогон дополнительно подтвердил путь `027228` → API → карточка `200300285_` с 23 шт.; один замер занял 6,9 с. Тестовые DOCX, XLSX, XLS, PDF и JPEG дали тот же товар после локального извлечения кода. Это не полная приёмка UC-01…05: сертификаты, подтверждённые аналоги, условия, реальная корзина и свободный AI-диалог остаются открытыми.

Для изменения также прошли проверка синтаксиса JavaScript, Ruff шлюза и `generate_ekt_catalog_openapi.py --check`. ESLint не смог запуститься из-за ошибки существующей конфигурации (`Converting circular structure to JSON` в цепочке конфигурации React); успешный результат линтера frontend не заявляется.

Общие тесты исходного шаблона запускаются `make test` для backend и `cd frontend && bun run test:e2e` для браузера. Они не заменяют проверки сценариев ekt.kz.

## Данные, внешние сервисы и ограничения

Материалы партнёра указывают `GET https://ekt.kz/api/products` (страницы через `?page=…`) и `GET https://ekt.kz/api/products/detail?id=…` с Basic Auth. Доступ, наблюдаемая схема и чтение контрольного товара из чата проверены 23.09.2026; подробности контракта — в [contracts/ekt-catalog-api.md](contracts/ekt-catalog-api.md) и [карте контрактов](contracts/README.md). Встроенная выборка подходит для демонстрации поведения, но не подтверждает актуальность остатков ekt.kz. Источник условий покупки, доступ к корзине и способ встраивания на действующий сайт предстоит уточнить. Публичного развёртывания кейса пока нет.

Документы хакатона находятся в `docs/source of truth/assets/`; перед публикацией проекта нужно проверить репозиторий на секреты и соблюдать правила организаторов по работе с данными.
