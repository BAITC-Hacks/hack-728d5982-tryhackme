# Ожидаемые выходы: что должен увидеть покупатель

Основание — разделы 5 и 7 [Word ТЗ](<../docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>). Ниже **шаблоны смысла ответа**, не записанные ответы модели. Значения в `<угловых скобках>` получаются при запуске. Фактический предыдущий прогон — [observed-session.json](observed-session.json), проверка файлов — [verification.json](verification.json). Дословное совпадение не требуется.

## 1. Текст → информация о товаре (UC-01)

**Покупатель:** `Есть ли 027005? Покажи характеристики и сертификат.`

**Ожидается в одном чате:**

> Найден товар по коду 027005. Артикул каталога — 200300274_.
> Наличие: <актуальный остаток и склады из карточки>.
> Характеристики: <подтверждённые значения полюсов, тока, напряжения и других существенных свойств>.
> Сертификат: <ссылка из источника либо сообщение об отсутствии сведений>.
> Цена: <значение каталога>; источник и время чтения указаны.

Это может быть короткое сообщение плюс товарная карточка, а не единый абзац LLM. Нельзя требовать «23 шт.» для любого товара или приписывать API валюту, если она не указана.

**Корзина:** без изменений.

## 2. Word / Excel / PDF / JPEG → распознанные строки → карточки (тот же UC-01)

**Покупатель:** один файл `inputs/specification.*` и `Покажи наличие и характеристики всех позиций из вложения.`

**Ожидается:**

- Видимый результат извлечения кодов `027005`, `027028`; запрос содержит количества 2 и 1 соответственно.
- Две проверенные карточки: ID `515280` / артикул `200300274_`, ID `515281` / артикул `200300275_`.
- В проверке спецификации количество указано для каждой строки. Отсутствующее количество помечено «Нужно количество», такая строка не выбрана. Значение 1 автоматически не подставляется. Неизвестный код, неоднозначность и нехватка остатка видны отдельными статусами.
- При неоднозначной строке — уточнение, а не незаметное исключение позиции или выдуманный товар.

Один и тот же документ в нескольких форматах не означает новые товары. Цены/остатки берутся из каталога после распознавания. **Извлечение документа не добавляет позиции в корзину.**

## 3. Нулевой остаток → предложение аналога (UC-02)

**Покупатель:** `Есть ли ярп4520 в наличии?` Подбор при отсутствии выполняется автоматически.

**Если исходный остаток остаётся нулевым, ожидается:**

> Исходная позиция отсутствует. Доступна проверенная альтернатива <артикул>.
> Почему подходит: <совпавшая модель/значимые параметры из данных>.
> Отличия: <отличия артикула, характеристик/исполнения, если известны>.
> Остаток: <актуальное значение из API>.

Контрольный найденный кандидат — `150200474_` / ID `18284`; это наблюдение предыдущего прогона, не обязательная подстановка ответа. Если источник изменился, оценивайте текущую доступность и обоснование, а не неизменность этого ID.

**Корзина:** без изменений; выбор аналога требует UC-04.

## 4. Вопрос об условиях → содержательная консультация (UC-03)

**Покупатель:** `Как оплатить, получить доставку и какая минимальная партия?`

**Ожидаются три блока:**

1. **Оплата:** способы и условия из опубликованного источника.
2. **Доставка:** применимые сроки/стоимость/территория из того же источника, с оговоркой о неопределённом тарифе, если данные неоднозначны.
3. **Минимальная партия:** общее правило, если опубликовано; иначе отсутствие сведений. Кратность конкретной позиции из карточки показана отдельно.

Приложение даёт ссылку на источник и время чтения. Оно не спрашивает номер карты/CVV и не проводит оплату. Не следует выдумывать общий минимум из `KRATNOST_MIN` одного товара.

**Корзина:** без изменений.

## 5. Предложение → отдельное согласие → изменение (UC-04)

**Покупатель:** `Подготовь добавление 2 шт 027005 и 1 шт 027028 в корзину.` → проверить две готовые строки → «Проверить выбранное».

**До согласия:**

> Проверьте выбранные позиции и количество. Для изменения корзины нужно отдельное подтверждение.
>
> 200300274_ — 2 шт. × <P1>.
> 200300275_ — 1 шт. × <P2>.
> Сумма: <2 × P1 + P2>.
>
> [Да, добавить] [Отмена]

Количество и цена соответствуют показанному предложению; если данных не хватает или количество недоступно, вместо него должна быть ошибка/уточнение.

| Момент | `200300274_` | `200300275_` | Счётчик |
| --- | --- | --- | --- |
| Новая пустая сессия | 0 | 0 | 0 |
| Показано предложение | 0 | 0 | 0 |
| Пользователь ответил «ок» | 0 | 0 | 0 |
| Отдельное «да, добавь», проверки пройдены | 2 | 1 | 3 |
| Повтор старого подтверждения | 2 | 1 | 3 |

**После согласия:** сообщение об обновлённой корзине и действующая ссылка. При ошибке повторной проверки ни одна строка набора не добавляется. Сумма не включает автоматически придуманные доставку, скидки, валюту или комиссии.

## 6. Ссылка → актуальное состояние (UC-05)

**Покупатель:** нажимает «Открыть корзину →».

**Ожидается:** `/cart`, две строки с указанными выше количествами и рассчитанной суммой, тот же результат после обновления страницы в действующей сессии. Количество единиц — 3, количество разных позиций — 2: это разные показатели.

Ссылка у всех посетителей может иметь одинаковый путь, но состояние определяется защищённой сессией. Она не является публичной ссылкой на чужую корзину. Заказ, резерв и списание денег этим действием не создаются.

## Как читать реальные артефакты

Прямой путь по XLSX отдельно сохранён в поле `file_to_cart`: количества 2 и 1 извлечены моделью из документа, до согласия корзина пуста, после подтверждения — 3 единицы. Это независимая сессия, а не ещё одно добавление в корзину основного прогона.

`manifest.json` задаёт только учебные входы и ожидаемое сопоставление. `verification.json` фиксирует проверку каждого сгенерированного файла. `observed-session.json` содержит проекцию реальных ответов: лишние свойства карточек, токены согласия и полный текст оплаты/доставки не сохранены; ссылка источника и результат проверки всех трёх тем сохранены в отчёте/сценарии. Это не новая схема API — контракт находится в [contracts/landing.openapi.json](../contracts/landing.openapi.json).

Числа из наблюдений действительны только на момент чтения. Успешное распознавание этих примеров не доказывает обработку любого сложного скана или фотографии без маркировки; положительный живой пример сертификата и старый DOC остаются открытыми в [ROADMAP](../ROADMAP.md).
