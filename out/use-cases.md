# Сценарии использования — пять Must have HackAlem

Нумерация **UC-01…05** строго соответствует пяти пунктам раздела 7 [Word ТЗ](<../docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>). Пользователь — частный покупатель или закупщик электротехники. Цель — получить сведения для выбора и перейти к своей корзине без типового обращения к менеджеру. Предусловия запуска и готовые файлы — в [README](README.md).

## UC-01. Узнать наличие, характеристики и получить сертификат

**ТЗ:** раздел 7, пункт 1; текст/вложения из раздела 5.

**Текстовый вход:** `Есть ли 027005? Покажи технические характеристики и сертификат.`

**Равноправный вход файлом:** приложить [specification.xlsx](inputs/specification.xlsx), [specification.docx](inputs/specification.docx), [specification.pdf](inputs/specification.pdf), [скан PDF](inputs/specification-scan.pdf) или [JPEG](inputs/specification.jpeg) и отправить `Покажи наличие и характеристики всех позиций из вложения.` Отправка только файла также допустима: интерфейс попросит разобрать вложения.

**Шаги:**

1. Открыть чат на лендинге. Ввести вопрос или прикрепить один файл и отправить сообщение.
2. Для файла посмотреть «Проверку спецификации»: код, количество и статус каждой распознанной позиции. Сверить с оригиналом; неизвестное, неоднозначное и недостающее количество уточнить до выбора.
3. Прочитать карточку: название/артикул, наличие, технические характеристики, документы. Раскрыть «Описание и остатки по складам».

**Что делает приложение:** модель извлекает смысл/позиции, сервер ищет товар, читает детальную карточку и выводит данные источника. Для Word и Excel перед LLM работает серверный парсер; для PDF и JPEG применяется мультимодальная модель.

**Наблюдаемый выход:** по `027005` — карточка `200300274_`, ID `515280`; для спецификации — также `027028` / `200300275_` / `515281`. Остатки и свойства соответствуют текущему API. Сертификат показан ссылкой, если он есть в данных; иначе есть сообщение об отсутствии сведений. Корзина не изменена.

**Как принять:** сверить ID/артикул и свойства с детальной карточкой источника; убедиться, что результат виден в чате на выбранном экране. Для файлов должны быть найдены обе позиции, а количества 2 и 1 — проверены в предложении UC-04. Текст ответа не обязан совпадать дословно с примером. Время измеряется: ТЗ ожидает единицы секунд, жёсткого числового порога не задаёт.

**Варианты того же UC:**

- `Есть ли UNKNOWN-99999?` → если точной позиции нет, запрос уточнения, без вымышленной цены/остатка.
- `Характеристики 027228` → показать обнаруженное расхождение 160 А в названии / 250 А в свойствах, если оно осталось в источнике. Не скрывать его.
- Сертификат отсутствует → сообщить об этом; это не отказ всего поиска. Живой положительный пример сертификата пока не подтверждён.
- Повреждённый/слишком большой файл или сбой источника → понятная ошибка, корзина прежняя. Нечитаемое фото → уточнение, не угаданный артикул.

## UC-02. Получить релевантный аналог отсутствующего товара

**ТЗ:** раздел 7, пункт 2; объяснимость из раздела 9.

**Вход:** `Есть ли артикул ярп4520 в наличии?` Аналог должен появиться при нулевом остатке без отдельной просьбы. Второй проверенный запрос: `Есть ли артикул 310100080_ в наличии?`.

**Шаги:** открыть карточку исходной позиции → убедиться, что остаток нулевой → прочитать предложенный доступный аналог и причину → при выборе перейти к UC-04. Также можно нажать «Найти аналог» у карточки.

**Наблюдаемый выход:** минимум один доступный аналог с проверенным артикулом и кратким обоснованием. В предыдущем живом прогоне исходный ID `45357` имел 0 шт.; найден ID `18284`, артикул `150200474_`. Полное обозначение LED STARK 30 W / 2400 Lm / 4000 K / IP20 и марка совпали; отличие артикула указано. Остаток аналога нужно читать заново при текущем запуске.

**Как принять:** исходный товар действительно отсутствует; аналог существует и доступен; причина ссылается на свойства/обозначение источника, существенные отличия видны. Предложение аналога само по себе не меняет корзину.

**Исключения:** если исходный остаток стал положительным, это уже не контроль отсутствующего товара — для повторной приёмки нужен другой нулевой остаток. Если релевантного аналога нет или параметры противоречат друг другу, приложение сообщает ограничение; такой ответ честен, но не заменяет успешный контрольный пример с доступным аналогом из ТЗ.

Известный незакрытый случай — `RM35BA10`. Показывать его как успешно подобранную замену нельзя. При защите результат связывается с критериями качества и объяснимости, а не с обещанием покрытия всего каталога. Порядок общего показа — [demo-day.md](demo-day.md).

## UC-03. Узнать условия покупки

**ТЗ:** раздел 7, пункт 3.

**Вход:** `Как оплатить покупку, получить доставку и какая минимальная партия?`

**Шаги:** задать вопрос → прочитать блоки «Оплата», «Доставка», «Минимальная партия» → открыть ссылку источника при необходимости. Для кратности конкретной позиции сначала запросить её карточку через UC-01.

**Наблюдаемый выход:** содержательная информация об оплате/доставке со ссылкой на опубликованные условия магазина; по минимуму — опубликованное правило либо явное отсутствие общего правила, отдельно минимальная кратность конкретного товара. Тарифы и сроки не берутся из текста LLM без источника.

**Как принять:** присутствуют все три темы; сведения сопоставимы с указанной страницей; неопределённые пороги доставки не объявлены однозначными. Корзина прежняя. Сейчас источник — `https://ekt.kz/checkout-delivery/`; общая минимальная партия на нём не опубликована, приложение это обозначает.

**Исключение:** источник недоступен/изменился → сообщение о невозможности проверить условия, без придуманных тарифов.

## UC-04. Добавить выбранное количество только после отдельного согласия

**ТЗ:** раздел 7, пункт 4; запреты раздела 9. Корзина текущей версии находится на нашей стороне по уточнению заказчика.

**Предусловие:** пустая корзина новой сессии; выбранные позиции найдены и запрошенные количества доступны. Для продолжения после файла используйте те же коды, что показаны в извлечении.

**Вход:** `Подготовь добавление 2 шт 027005 и 1 шт 027028 в корзину.`

**Вариант с количеством из файла:** в новой сессии приложите [specification.xlsx](inputs/specification.xlsx) и отправьте `Подготовь предложение добавить в корзину все позиции и количества из приложенной спецификации.` Проверьте обе позиции и количества 2 и 1 в разборе. Даже просьба собрать корзину сначала показывает выбор строк: нажмите «Проверить выбранное», затем подтвердите состав отдельно.

**Шаги:**

1. Отправить запрос. Альтернатива для одной позиции — выбрать количество в карточке и нажать «В корзину».
2. Для файла или нескольких товаров в «Проверке спецификации» отметить нужные готовые строки и нажать «Проверить выбранное». Неотмеченные позиции и аналоги не попадут в партию. Проверить предложение: код/артикул, количество каждой строки, сумма по цене каталога. **Корзина ещё пуста.**
3. Отправить `ок`. Корзина по-прежнему пуста; требуется отдельное явное согласие.
4. Отправить `да, добавь` либо нажать «Да, добавить» у действующего предложения.
5. Дождаться сообщения об изменении корзины и ссылки. Сервер повторно проверяет цену, кратность и остаток перед применением всех строк.

**Наблюдаемый выход:** добавлены `200300274_` — 2 шт. и `200300275_` — 1 шт.; суммарно 3 единицы. Если исходная корзина была непустой, сравнивайте прирост нужных строк, а не абсолютный счётчик. Сумма вычисляется из цен, показанных в принятом предложении. Это не резерв и не оформленный заказ магазина.

**Как принять:** снимок до предложения = снимок до явного согласия; после согласия изменились только выбранные позиции. Итоговое количество с учётом ранее добавленного не превышает остаток. Повтор прежнего подтверждения не добавляет повторно.

**Обязательные отрицательные ветки:**

| Действие | Ожидаемый результат |
| --- | --- |
| «Ок», файл с текстом согласия, анализ спецификации | Состав корзины не меняется. |
| «Отмена» до согласия, затем «да, добавь» | Отменённое предложение не применяется. |
| Изменить количество или выбрать другой товар | Старое согласие недействительно; нужно новое предложение. |
| Запросить больше доступного остатка, 0 или отрицательное количество | Ошибка/уточнение; корзина не меняется. |
| Подтвердить позже 3 минут или после изменения цены/остатка | Повторный выбор и согласие; скрытого уменьшения количества нет. |
| В наборе одна позиция перестала быть доступной | Не добавляется часть набора без нового согласования. |

## UC-05. Открыть актуальную корзину по прямой ссылке

**ТЗ:** раздел 7, пункт 5; завершение ключевого пути раздела 3.

**Вход:** успешный UC-04; повторно писать товар не требуется.

**Шаги:** нажать «Открыть корзину →» → проверить строки → обновить страницу → проверить сохранённое состояние.

**Наблюдаемый выход:** адрес `/cart`, актуальная корзина той же сессии внутри того же окна чата. В контрольном примере две строки с количеством 2 и 1, счётчик 3, сумма соответствует их стоимости. Другой посетитель не получает эту корзину, просто открыв тот же путь `/cart`.

**Как принять:** ссылка работает, артикулы/количество соответствуют подтверждённым, обновление страницы не теряет состояние в действующей сессии. Корзина принадлежит нашему приложению; оплата и оформление заказа на ekt.kz сейчас не реализованы. ТЗ допускает прямую ссылку на корзину/оформление; не нужно выдавать посещение `/cart` за создание заказа.

**Исключения:** час бездействия или перезапуск сервера очищает память сессии; долгосрочное хранение — следующий этап. После ошибки UC-04 нельзя сообщать об успешном добавлении или показывать вымышленный состав.

## Сквозная демонстрация

`Текст или один файл → UC-01 → при нулевом остатке UC-02 → при вопросе об условиях UC-03 → выбор и отдельное согласие UC-04 → ссылка UC-05`.

UC-02 и UC-03 — ответвления по потребности клиента; покупатель не обязан проходить их перед каждой покупкой. Единственное обязательное условие изменения корзины — явное согласие с проверенным составом и количеством. [Примеры ожидаемых выходов](expected-results.md) позволяют проверить смысл результата без требования к дословной формулировке LLM.
