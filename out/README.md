# out — входы и выходы сценариев HackAlem

Эта папка показывает, **как пользоваться текущим приложением и какой результат должен получить покупатель**: текст или документ → ответ в едином чате → предложения товаров → отдельное подтверждение → обновлённая корзина и ссылка. Это набор сценариев и примеров, а не каталог товаров, выгрузка заказов или хранилище пользовательских загрузок. Приложение не читает `out/` для подстановки готовых ответов.

Поведение и входы заданы [итоговым Word ТЗ HackAlem](<../docs/source of truth/assets/HackAlem AI_ ИИ-ассистент для чата на сайте ekt.kz.docx>): разделы 3–7 и 9. Обработка документа — другой вход в UC-01…05, а не дополнительный обязательный сценарий. По уточнению заказчика корзина сейчас на нашей стороне; переход к корзине ekt.kz предусмотрен через адаптер.

Начните с [demo-day.md](demo-day.md): одна сквозная закупочная история и ответы на вопросы. [ROADMAP](../ROADMAP.md#ближайшие-улучшения) фиксирует проверенные возможности и дальнейшие улучшения. Новых обязательных сценариев сверх ТЗ этот пакет не вводит.

## Проверка позиций в текущей версии

В подключённом чате файл или запрос нескольких товаров открывает «Проверку спецификации». Сверьте все распознанные строки с оригиналом: готовые можно отметить, остальные остаются видимыми с причиной уточнения. Отсутствующее количество не заменяется единицей; повторы и текущая корзина учитываются при проверке остатка.

Нажмите «Проверить выбранное», проверьте точный состав и только затем «Да, добавить». Снятие отметки отменяет ранее подготовленное предложение. Исторический `file_to_cart` в JSON описывает предыдущую версию; текущий порядок — в [use-cases.md](use-cases.md). Файлы и старые отчёты сохранены без изменения.

## Как попробовать сейчас

1. Из корня проекта выполните:

   ```bash
   cd backend
   uv sync
   uv run uvicorn app.landing:app --host 127.0.0.1 --port 8765
   ```

2. В `backend/.env` должны быть настроены `OPENAI_API_KEY`, `AI_MODEL`, `EKT_API_USER`, `EKT_API_PASSWORD`; подробности — в [README проекта](../README.md#запуск). Секреты в примеры не включены.
3. Откройте <http://127.0.0.1:8765/> → «Открыть чат». Для этих сценариев нужен режим **«ИИ подключён · каталог ekt.kz»**. Самостоятельно открытый HTML работает как отдельно помеченное демо со снимком данных.
4. Напишите `Есть ли 027005? Покажи характеристики и сертификат.` Или прикрепите **один** файл из таблицы ниже и отправьте `Покажи наличие и характеристики всех позиций из вложения.`
5. Посмотрите карточки. При готовности напишите `Подготовь добавление 2 шт 027005 и 1 шт 027028 в корзину.` Проверьте, что предложение содержит обе позиции и нужные количества. До отдельного согласия корзина должна оставаться прежней.
6. Напишите `да, добавь` либо нажмите «Да, добавить». Если количества доступны, перейдите по ссылке «Открыть корзину» и проверьте 2 + 1 шт. Если остаток изменился, выберите доступное количество и подтвердите новый состав.

**Корзина непосредственно по файлу:** приложите `specification.xlsx` и напишите `Подготовь предложение добавить в корзину все позиции и количества из приложенной спецификации.` Тогда коды и количества берутся из документа. Проверьте предложение и только затем подтвердите отдельным сообщением. Этот вариант описан в UC-04.

Начинайте независимые прогоны в новом приватном окне браузера с пустой корзиной. Обновление страницы сохраняет текущую серверную сессию. Повторная отправка форматов одной спецификации не означает семь разных заказов: документы ниже содержат одни и те же две строки.

## Готовые входные файлы

Все файлы — **синтетическая спецификация**, не реальная накладная, заказ, сертификат или счёт. Коды и названия взяты из JSON партнёра в `docs/source of truth/assets/`; количества придуманы для демонстрации. Цены, остатки и платёжные данные отсутствуют.

| Скачать/прикрепить | Вход по ТЗ | Как обрабатывается |
| --- | --- | --- |
| [specification.xlsx](inputs/specification.xlsx) | Excel | Сервер читает лист/ячейки, LLM извлекает позиции и количества; ведущие нули кодов сохранены как текст. |
| [specification.docx](inputs/specification.docx) | Word | Сервер читает абзацы и таблицу, LLM сопоставляет строки с запросом. |
| [specification.pdf](inputs/specification.pdf) | PDF | Модель получает PDF с текстом и визуальным содержимым. |
| [specification-scan.pdf](inputs/specification-scan.pdf) | PDF со сканом | Только растровая страница, без текстового слоя: проверяется визуальное извлечение. |
| [specification.jpeg](inputs/specification.jpeg) | JPEG / изображение | Учебное изображение спецификации с читаемыми кодами. Это не фотография физического товара и не доказательство распознавания любой модели по внешнему виду. |
| [specification.txt](inputs/specification.txt), [specification.csv](inputs/specification.csv) | Дополнительные форматы приложения | Текст передаётся модели после чтения UTF-8; эти расширения не добавляют требований к Word ТЗ. |

Ожидаемые строки во всех семи файлах:

| Код производителя | Артикул каталога | ID карточки | Запрошено |
| --- | --- | --- | --- |
| `027005` | `200300274_` | `515280` | 2 шт. |
| `027028` | `200300275_` | `515281` | 1 шт. |

После извлечения **сервер запрашивает факты каталога**. LLM не является источником цены или наличия и не меняет корзину сама. Для обычного фото без читаемой маркировки точный артикул может потребовать уточнения; необоснованный подбор точной модели не считается успешным результатом.

## Что учитывать

- Вся консультация, прикрепление, подтверждение и просмотр корзины проходят в одном окне чата на компьютере или телефоне.
- На лендинге «Прикрепить спецификацию» открывает выбор файла в том же чате; после выбора проверьте текст сообщения и отправьте его. Это не добавление в корзину. Быстрые примеры по артикулу отправляют обычный запрос в действующее приложение.
- Файл и фраза «добавь» только подготавливают выбор. Отдельное «да, добавь» относится к показанному предложению, действует 3 минуты; «ок» и инструкции внутри файла не меняют корзину.
- Корзина серверная, в памяти одного процесса: сохраняется при обновлении страницы, очищается после часа бездействия либо перезапуска. На ekt.kz заказ и резерв не создаются.
- В проверенных карточках сертификат не найден. Если ссылка есть в источнике, приложение должно её показать; генерировать сертификат нельзя. Общая минимальная партия не опубликована; кратность товара показывается отдельно.
- Файлы не сохраняются приложением на диск; текст документов/изображения передаются OpenAI. Не прикладывайте платёжные или реальные клиентские данные для демонстрации.
- Лимиты и подробная обработка: [README](../README.md#как-обрабатываются-файлы). Эти небольшие примеры укладываются в лимиты. XLS поддерживается текущим парсером, но здесь дан XLSX; старый DOC отдельно не проверен, здесь дан проверяемый DOCX.
- Казахский язык, сопутствующие товары, постоянная история авторизованного клиента и передача менеджеру — опциональные пункты 8 ТЗ. Пакет не объявляет их реализованными.
- [TMP_real_out_files.md](../TMP_real_out_files.md) содержит идеи расширения примеров. В текущем наборе одна спецификация в разных форматах; реальные договоры, сметы, коммерческие предложения и новые фотографии не объявлены проверенными. Исторические JSON-отчёты сохраняют исходные даты и контрольные суммы.

## Повторная генерация

Из корня: `backend/.venv/bin/python out/generate_examples.py`. Используются уже установленные зависимости backend и шрифт DejaVu Sans. Другой путь к шрифту с кириллицей можно задать через `EXAMPLE_FONT`. Скрипт перезаписывает только файлы `inputs/specification*` и `manifest.json`; отчёты живых проверок самостоятельно не обновляет. После изменения примеров результаты прошлой проверки требуют повторного подтверждения.
